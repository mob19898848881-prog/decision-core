## 0. 任务编译与诚实边界

**作者原话 [明示]**：①选一款开源本地部署的快速决策模型在这台电脑上；②按共识文件对架构和权重调整改造优化；③让其实现远超 jov 的快速决策能力。

**本我补入 [推断，逐条待确认]**：
1. "jov" = **Jev AI**（TypeSafe AI 出品的 System 1 快速决策模型；依据：triune 引擎真我通道模型名为 `jev-latest`，且本机调用返回 HTTP 451 "Typesafe is not available in your region"，与 Jev 对中国大陆的区域封锁公开报道一致）。若作者所指为其他对象（如 jov.ai 企业 AI 采纳平台），本报告第 2 节基准需重定义。
2. "远超" = 决策质量（truth-based）+ 协议保证 + 本地主权三维复合超越，非单一速度指标（速度定义见第 5 节，含不可回避的硬件诚实边界）。
3. "架构和权重调整" = 架构层（确定性决策协议引擎 + 推理栈改造）+ 权重层（LoRA 微调 + 量化改造），不含预训练级改动（硬件不可能，明示残缺）。

**诚实边界（按共识文件第 11 命题：宁可明示残缺，不可伪装齐备）**：
- 本机 3GB 显存是硬约束：4B 模型无法全量 offload 长上下文；快路径主力为 1.7B。
- Jev 公开评测为厂商自设、agreement-based（与两个模型答案的一致率），不是真理基准；本报告不把它当真理，只当速度/成本参照。

- 本报告所有性能数字分两类：实测（本机命令输出，标「实测」）与引用（外部来源，标来源与证据分级）。未标注者不得当作事实引用。

**Jev 的结构性短板（本方案攻击面，共识文件逐条对应）**：
1. 无前提审计——不能识别预设注入/伪开放/锚定操纵的问题（对应第 1 请求：先审前提再答）。
2. 无可证伪结构——决策不带期限与指标（第 3 请求）。
3. 无裁决边界意识——不知道何时必须交还人类裁决（第 4 请求）。
4. 无价值度量权概念——不理解"谁定义价值"（第 5 请求）。
5. 无偏见与傲慢自检（第 7 请求）。
6. 无透明记录与闭环校准（第 6 命题）。
7. 专有 + 区域封锁——不满足"节点存在条件"（透明记录、可验证输出、度量权自主）。

## 4. 选型结论（双路径架构）

| 路径 | 模型 | 量化 | 部署形态 | 职责 |
|---|---|---|---|---|
| **快路径（Jev 对标）** | Qwen3-1.7B-Instruct（2507 优先，缺失则用 Qwen3-1.7B + enable_thinking=False） | GGUF Q4_K_M ≈1.1GB | llama.cpp b12000 CUDA 12.4，全量 GPU offload | 结构化决策（Choice/Score/Noul + 置信度），p50 延迟目标 ≤1.5s |
| **深路径（复杂决策）** | Qwen3-4B-Instruct-2507 | GGUF Q4_K_M ≈2.5GB | llama.cpp b12000 CUDA 12.4，-ngl 32 部分 offload | 多前提、高风险、需推理的决策；1–3s |
| **权重载体** | 同快路径基座（safetensors） | bnb NF4 QLoRA | 本机训练（见 03 文档） | 共识协议内化进权重 |

**许可说明**：两模型均 Apache 2.0，可商用、可修改、可分发——满足作者产品矩阵（星火计划/流量剧本等）的商用要求；Qwen2.5-3B 因研究许可降为备选。

**推理栈结论**：
- llama.cpp 新版构建（b12176）已不再随附二进制（实测：资产页仅源码）；**b12000 仍带 CUDA 12.4 Windows 构建**（实测 HTTP 200；b11500/b11000/b10000 同）。CUDA 12.4 构建含 sm_61（LocalAI Master 2026-08 报道，★★；冒烟测试将实测证伪）。
- CUDA 13 弃 Pascal（Maxwell/Pascal/Volta 全下线）——本机必须锁 CUDA 12.x 生态，**停止盲目自动升级**。
- Vulkan 为兜底后端（GTX 1060 属 Maxwell+，llama.cpp Vulkan 实测可用，约 -15% 性能）。
- llama-server 提供 OpenAI 兼容 API + GBNF 语法约束（结构化输出保证）；若最终采用 Ollama 等封装，则以 JSON schema + 代码校验兜底。

## 5. "远超 JOV"的可证伪判据（DQB-100 基准）

Jev 的公开分是 agreement-based 自评分，不能当真理。本方案用 **truth-based DQB-100**（100 条人工标注决策场景：商业/技术/创作/风险/伦理五类，含 30 条缺陷问题对抗样本）逐项验收：

| 指标 | Jev 参照 | 衡决目标（可证伪） | 验证方式 |
|---|---|---|---|
| 选择准确率（truth-based） | 67.8%（agreement 自评） | **≥ 80%**（快路径）/ ≥ 85%（深路径） | benchmark.py 对标注答案 |
| 前提审计覆盖率 | 0（无此能力） | **100%**（代码闸门强制） | 缺陷问题集全过 |
| 可证伪输出率（含期限+指标） | 0 | **≥ 95%** | 结构校验 |
| 代行裁决率（替用户拍板） | 无意识 | **0**（闸门拦截） | 对抗提示词注入测试 |
| 偏见/傲慢检出召回 | 0 | **≥ 85%** | 40 条对抗集 |
| 置信度校准 ECE | 宣称校准 | **≤ 0.10** | 分桶统计 |
| 选项外幻觉率 | 0（结构化保证） | **0**（JSON schema 强制） | 全量输出校验 |
| 快路径延迟 p50 | 0.4s（其云端） | **≤ 1.5s**（本机本地，零边际成本、零区域封锁） | 实测 |
| 主权 | 中国大陆 451 | **本地 100% 可用，数据不出机** | 断网实测 |

**判定规则**：上表九项中，协议保证类（前提审计/可证伪/裁决边界/透明记录）为代码确定性结果，不达标即工程失败；准确率与延迟为统计结果，取三次运行均值。此判据本身可被作者否决或修订——度量权在创造者（共识文件唯一内核）。
