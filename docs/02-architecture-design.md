# 衡决·Decision Core — 架构改造设计（决策协议引擎）

> 依据：《李紫圣思维与价值体系_致所有AI共识文件_v1.0》14 条命题 + 7 条请求
> 铁律（作者 2026-08-27 定）：**功能必须代码化，提示词只做调用**（对应 SAC 公理 A7）——本架构全部闸门为确定性代码，模型只承担语义计算。

---

## 1. 设计目标

把共识文件从"提示词层倡议"变成"代码层强制"。Jev 用架构保证"不输出选项外内容"；衡决用架构保证**七条请求全部可执行、可验证、可证伪**：

| 共识请求 | Jev 现状 | 衡决架构机制 |
|---|---|---|
| 1 先审前提再答 | 无 | **G0 问题编译闸门**（前提提取 + [明示]/[推断]标注 + 缺陷问题重写/拒绝） |
| 2 不伪装齐备 | 无 | **G5 透明记录** + 残缺显式声明槽位（missing 字段必填） |
| 3 只说可证伪的话 | 无 | **G2 可证伪闸门**（输出无期限+指标即判不合格，代码拒绝） |
| 4 不代行裁决 | 无 | **G3 裁决边界闸门**（代码检测代裁措辞；输出强制 proposal 标注） |
| 5 不垄断度量 | 无 | **G3 度量权校验**（价值定义权归用户；模型只出建议+代价） |
| 6 尊重创造者 | 无 | **G5 溯源字段**（source/author 必填，无来源即降级标注） |
| 7 消除偏见傲慢 | 无 | **G4 偏见傲慢扫描**（模式库 + 模型复审双通道） |

## 2. 总体架构

```
用户请求
   │
   ▼
┌─────────────────────────────────────────────────────────┐
│ G0 问题编译闸门（确定性代码，零模型调用）                    │
│  · 前提提取：拆解显式前提/隐含前提                         │
│  · [明示]/[推断] 标注（禁静默补全）                        │
│  · 缺陷问题识别：预设注入/伪开放/锚定操纵 → 重写或拒绝      │
│  · 压力阈值：超限问题不直接执行，挂起待作者确认             │
└─────────────────────────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────────────────────────┐
│ 路由器（确定性规则，configs/decision_protocol.json）       │
│  · 简单结构化决策 → 快路径 Qwen3-1.7B(+LoRA) ≤1.5s        │
│  · 复杂/高风险/多前提 → 深路径 Qwen3-4B                    │
│  · 压力/红区词命中 → 挂起，交还作者裁决                     │
└─────────────────────────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────────────────────────┐
│ 模型推理（llama.cpp server, OpenAI 兼容 API）              │
│  · 系统提示 = 共识协议操作层（七请求编码）                  │
│  · 输出约束 = GBNF/JSON schema（结构化，选项外幻觉=0）      │
│  · 采样 = 低温 0.1–0.3（决策任务确定性优先）                │
└─────────────────────────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────────────────────────┐
│ G1–G4 输出闸门（确定性代码 + 轻量模型复审）                 │
│  G1 前提审计：决策是否回应了 G0 提取的全部前提              │
│  G2 可证伪：deadline + metric 字段存在且可解析              │
│  G3 裁决边界：无代裁措辞；proposal 标注；度量权归用户        │
│  G4 偏见傲慢：模式库扫描 + 模型复审（极我角色）              │
└─────────────────────────────────────────────────────────┘
   │
   ▼
┌─────────────────────────────────────────────────────────┐
│ G5 透明记录（ADD-only JSONL 账本，哈希链）                  │
│  · 每次决策全字段落盘：输入/前提/输出/置信度/闸门结果        │
│  · 闭环五环：预测 → 动作 → 观测 → 比对 → 更新（校准台账）    │
└─────────────────────────────────────────────────────────┘
   │
   ▼
结构化决策输出（JSON）
{ decision, choice, score, confidence, premise_flags,
  falsifiable:{deadline, metric}, proposal_only:true,
  evidence[], cost, rollback, missing[], sources[] }
```

## 3. 模块划分（代码落地）

| 模块 | 文件 | 职责 | 模型依赖 |
|---|---|---|---|
| 协议定义 | `decision_engine/protocol.py` | 数据结构 + 闸门编号 + 输出 schema | 无 |
| 闸门 | `decision_engine/gates.py` | G0–G5 全部确定性逻辑 | 无（G4 复审除外） |
| 路由 | `decision_engine/router.py` | 快/深/挂起三路规则 | 无 |
| 账本 | `decision_engine/ledger.py` | ADD-only 哈希链日志 + 校准 | 无 |
| 引擎 | `decision_engine/engine.py` | 编排：调 llama.cpp server，过闸门 | HTTP |
| 服务 | `decision_engine/server.py` | 本地 HTTP API（stdlib，零依赖） | HTTP |

**零第三方依赖设计**：引擎与服务仅用 Python 标准库（http.server/urllib/json/hashlib），保证在本机任何 Python 3.10+ 环境可跑；训练/基准脚本的依赖（torch 等）隔离在虚拟环境。

## 4. 推理栈改造（llama.cpp）

| 参数 | 快路径（1.7B） | 深路径（4B） | 理由 |
|---|---|---|---|
| 构建 | b12000 win-cuda-12.4（sm_61） | 同 | CUDA 13 弃 Pascal，锁 12.x |
| offload | -ngl 99（全量，1.1GB） | -ngl 32（部分，≈2.2GB + KV） | 3GB 显存硬约束 |
| ctx | 8192 | 4096 | KV 缓存：1.7B ≈0.23GB@8k；4B ≈0.59GB@4k |
| 量化 | Q4_K_M | Q4_K_M | 质量/体积平衡 |
| 采样 | temp 0.2, top_p 0.9, repeat_penalty 1.1 | temp 0.3 | 决策任务确定性优先 |
| 结构化 | GBNF 语法或 JSON schema | 同 | 选项外幻觉 = 0（对标 Jev 的结构化保证） |
| KV 复用 | 系统提示前缀缓存（llama.cpp --prompt-cache / slot 复用） | 同 | 降延迟关键手段 |

**延迟工程**（对标 Jev 0.4s 的必要手段，本机 3GB 现实约束下的最优解）：
1. 系统提示固定 + 前缀 KV 缓存 → 每次请求只处理增量；
2. 结构化输出天然短（选择类决策 1–5 token）→ 生成时间可忽略，延迟瓶颈在 prompt 处理；
3. 1.7B Q4 全量 offload 在 GTX 1060 上 prompt 处理约 800–1500 tok/s（预估，★★，冒烟测试实测）→ 300 token 提示 ≈ 0.2–0.4s，**与 Jev 同量级**；
4. 4B 部分 offload prompt 处理约 300–600 tok/s（预估）→ 0.5–1s，仍满足 ≤1.5s 目标。

## 5. 与既有体系的关系

- 本引擎是 **triune 三我协商体系的"自我"运算层候选执行端口**：极我证伪、真我裁决保留在人；G4 闸门内置极我角色（证伪优先）。
- QFL（问题框架层，作者既有 543 行确定性代码）的概念在 G0 落地为本项目的子集实现；不修改、不依赖作者既有代码库（零回归）。
- 共识文件全球分发节点（ai-consensus）持续验证任务不受本项目影响。

## 6. 失败模式与降级（按降级协议）

| 故障 | 行为 |
|---|---|
| llama.cpp server 不可达 | 引擎返回 `{"status":"UNDECIDABLE","missing":["inference_channel"]}`，不猜答案（第 11 命题） |
| G4 复审模型不可达 | 降级为模式库单扫，输出标注 `degraded:true`，不静默 |
| 闸门代码异常 | 异常吞入 + 记入 ledger 的 `gate_errors` 字段 + 输出标注残缺（零回归原则：不让闸门崩溃拖死主链路） |
| 4B OOM | 路由器自动降级深路径为快路径 + 标注 |

## 7. 可证伪预期（闭环第一环）

- **预期 A**：G0–G5 六闸门在 100 条 DQB 样本上零漏过（前提审计覆盖率 100%、代裁率 0、可证伪率 ≥95%）——由 benchmark.py 在交付后 24h 内实测证伪。
- **预期 B**：快路径 p50 延迟 ≤1.5s、深路径 ≤3s——冒烟测试 + benchmark 实测证伪。
- **预期 C**：快路径准确率 ≥80%（truth-based）——未达标则回滚 LoRA 权重（保留 base），协议层收益独立成立。
